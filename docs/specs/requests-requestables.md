# Requests / Requestables — LOCKED brief (a pillar of Parvus Gather)

## Plain definition (anchor)
A **Requestable** is a **to-do item that someone requests of a user or a group.** Someone — a leader, another member, or a system flow — asks someone to do a thing; it shows up in their requests list; they do it or decline; the requester can see whether it's done.

Mechanically it's a **ticket** (requested → assigned → worked → done, tracked), and it works **group-wide** — a group has a shared board/queue of requestables that get assigned to members or claimed.

## Voice / tone — NON-NEGOTIABLE
These people are **volunteers; this is not a job.** Every word a volunteer sees stays an invitation, never an order:
- "request" / "asked" / "can you help" — NEVER "task assigned," "your queue," "overdue ticket," "action required," or any corporate task-tracker tone.
- Gratitude on completion. Reminders are gentle nudges, never nagging.
- This is the whole reason the name is "Requestable" — the soft framing lives in the model so nobody builds a corporate task UI on it. Pairs with the existing "design rules for older volunteers."

## What a Requestable HAS (exactly these — and KEEP IT LIGHTWEIGHT beyond them)
- A **requester** and an **assignee** — a single **user** OR a **group/role** (whoever-can-help claims it)
- **Status:** open → assigned → in-progress → done (plus declined / cancelled)
- **Priority**
- **Due date**
- **Comments / discussion** thread
- **Recurring** (repeats on a schedule)
- **Subtasks** (a small checklist within it)
- A **link to its source** (the join-request, meeting, sign-up that spawned it)

**KEEP IT LIGHTWEIGHT.** Those capabilities and nothing more — no SLAs, no custom fields, no automation rules, no approval-chain workflows, no enterprise ticketing cruft. Simple, warm, fast.

## Scope (group-centric)
Each **group** (ministry / board / committee) has its own board/queue of requestables. A leader assigns one to a member, or a member claims it. Each person has a personal **"my requests"** inbox across their groups. *("What's next for me?" is the personal view of this.)*

## Every Gather flow becomes a Requestable
Request-to-Join, meeting action items, sign-up / shift needs, approvals, applications, staff-assigned to-dos — all create Requestables in this one shared system instead of each reinventing pending/assign/track logic.
